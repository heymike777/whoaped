# Product analytics in one GA4 property

Use the existing WhoAped Firebase project and its linked GA4 property. The native iOS and Android apps use `@react-native-firebase/analytics`; the landing page uses its GA4 Web stream after consent; the Telegram bot forwards from MongoDB through Measurement Protocol to a separate Web stream. Each surface has its own stream, making filtering possible in GA4. Do not interpret GA4's cross-platform total users as a de-duplicated count of people: one person may have a website browser, app installation and Telegram chat with separate identifiers.

The mobile app logs tab `screen_view` events and manual wallet add/remove successes and failures, without addresses, transaction hashes or wallet names. Firebase automatically collects app lifecycle events when Analytics is enabled. Before releasing a mobile build, enable Google Analytics on the Firebase project (if it is not already linked), refresh the iOS `GoogleService-Info.plist` and Android `google-services.json` for `com.whoaped.app`, and confirm the app streams appear in the same GA4 property. The checked-in iOS plist currently has `IS_ANALYTICS_ENABLED=false`; do not claim mobile analytics is live until this is updated and a build is installed. Update App Store / Play privacy disclosures as appropriate before release.

For the bot stream and exact-count caveats, see [telegram-analytics.md](telegram-analytics.md). Verify an opt-in landing page view, one mobile `wallet_added`, and one bot `telegram_wallet_added` in GA4 Realtime/DebugView before relying on reports. Custom event parameters such as `command_name` may need custom dimensions registered in GA4 to appear in standard reports.
